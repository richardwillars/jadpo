# Jadpo language design issue log

**Status:** active  
**Purpose:** prevent compiler implementation from silently deciding unresolved
language semantics

An issue is resolved only by updating the relevant specification, decision
register, examples, and—once present—compiler fixtures.

## Status vocabulary

- `open` — no accepted decision;
- `provisional` — implementation may proceed behind fixtures, but golden apps
  may change it;
- `deferred` — intentionally outside the current compiler phase;
- `resolved` — reflected consistently in authoritative documentation.

## Issue discovery rule

If implementation requires a semantic choice not covered by an accepted or
provisional entry, stop that implementation path and add an issue here. Do not
hide the choice inside an AST shape, runtime helper, generated convention, or
test expectation.
